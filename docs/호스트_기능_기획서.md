# 프빗 호스트 기능 기획서

호스트(공간 운영자)가 프빗에 들어와서, 등록하고, 예약을 받고, 운영하는 전 과정을 정리한 문서입니다. 현재 구현된 범위와 다음 단계를 구분해 적었습니다.

## 1. 호스트 여정 한눈에

```
발견 ─▶ 입점 안내(/host) ─▶ 입점 신청(/host/apply, 6단계) ─▶ 검수(2~3일) ─▶ 인증·노출
                                                                            │
     운영 ◀─ 호스트 센터(/host/center) ◀─ 예약 요청·문의 수신 ◀─────────────┘
       │
       ├─ 예약 관리: 요청 → 확정 → 이용완료 → 정산
       ├─ 핫딜·프로모션 신청
       ├─ 정보 수정 요청 / 사진 등록
       └─ 후기·문의 응답
```

## 2. 입점 (Onboarding)

### 2-1. 입점 안내 페이지 `/host`
- 프라이빗 기준 5항목(필수 4 + 선택 1)을 먼저 보여줘 '우리 공간이 대상인지'를 바로 판단하게 함
- 입점 혜택 4가지, 절차 4단계, 호스트 센터 기능, 요금 구조(기본 무료 / 노출 부스트 / 인증 프로그램), 호스트 FAQ, 광고·제휴 문의 폼
- JSON-LD: HowTo(입점 절차), FAQPage

### 2-2. 입점 신청 위저드 `/host/apply`

| 단계 | 입력 | 검증 규칙 |
|---|---|---|
| 1 프라이빗 기준 | 독립 공간 / 단독 이용 / 예약제 / 외부인 미출입 (필수), 룸 내 화장실·샤워실 (선택) | 필수 4개 모두 체크 |
| 2 사업자·대표 | 공간명, 대표자, 연락처, 이메일(=호스트 센터 ID), 사업자번호(선택), 주소 | 전화·이메일 형식 |
| 3 공간 정보 | 카테고리/세부유형, 인원 min~max, 면적, 운영시간·요일, 시설 토글 15종(검색 필터와 동일), 주요 시설, 소개(20자+), 프라이빗 이용 방식 | 카테고리·소개·프라이빗 방식 필수 |
| 4 요금·정책 | 요금 체계(시간당/타임제/패키지/코스제), 기본·주말·추가인원·심야·보증금, 취소정책 템플릿(유연/표준/엄격/직접), 예약 접수 방식(네이버예약/자체/카카오/전화/프빗) | 기본 요금·접수 방식 1개+ |
| 5 채널·사진 | 네이버지도 URL, 예약 URL, 홈페이지, 인스타, 카카오채널, 사진 최대 10장(드래그 업로드·미리보기) | 채널 1개 이상 |
| 6 검토·제출 | 전체 요약 + 동의 3항목(진위·연락·기준 준수) | 3개 동의 |

- 작성 중 자동 저장(localStorage, 0.6초 디바운스) → 중간에 나가도 이어서 작성
- 상세 페이지의 "이 공간을 운영하시나요?" 링크(`/host/apply?claim=PVIT-xxxx`)로 들어오면 기존 데이터가 미리 채워짐 (운영자 클레임)
- 제출 → `POST /api/host/apply` → 접수번호 `PV-YYYYMMDD-XXXX` 발급 → 호스트 세션 자동 생성 → 완료 화면(다음 단계 안내)

### 2-3. 검수 기준 (DB 검증 리포트의 원칙을 그대로 적용)
- 상호명 · 도로명주소 · 지도 장소 URL · 공개 연락처 중 **3개 이상 일치** → 승인(A 호스트 인증)
- 프라이빗 기준 미충족 → 보완 요청(fix) 상태로 호스트 센터에 사유 표시
- 승인 시 `spaces.json` 해당 항목에 `grade:"A"`, `tel`, `img`, `reserve`, `home` 을 채우면 사이트에 즉시 반영

## 3. 호스트 센터 `/host/center`

로그인: 입점 신청 시 이메일 + 접수번호 (현재는 이 기기에 저장된 신청 내역 기준). "데모로 둘러보기"로 샘플 데이터 체험 가능. 정식 계정 시스템 연동 시 이 게이트만 교체.

| 탭 | 기능 | 구현 상태 |
|---|---|---|
| 대시보드 | 확인 대기 예약·확정·미답변 문의·등록 공간 수, 공간 검수 진행 단계, 대기 예약 즉시 확정/거절, 할 일 | 완료 |
| 내 공간 | 공간 카드(상태·사진 수·요금·노출 ON/OFF), 등록 내용 요약, 정보 수정 요청 폼(`/api/contact` type=fix), 사진 등록, 지점 추가 | 완료 |
| 예약 관리 | 주간 캘린더(확정=초록/대기=노랑), 상태 필터, 예약 상세(확정·거절·이용완료·취소·고객 전화), 프빗 요청 표시 | 완료 (월간 캘린더·네이버예약 동기화는 다음) |
| 정산 | 정산 구조 안내, 이용 완료 건수·금액(참고값), 정산 주기·계좌 상태, 완료 내역 | 구조 완료 (자체 결제 오픈 시 실데이터) |
| 핫딜·프로모션 | 핫딜 신청(종류·기간·요일·시간·원가·할인가·수량, 할인율 자동계산) → `/api/contact` type=deal, 노출 부스트·인증 프로그램 관심 등록 | 완료 |
| 문의·후기 | 고객 문의 답변(엔터 전송), 후기 응대 안내 | 완료 (후기 실데이터는 커뮤니티 백엔드 연동 시) |
| 설정 | 계정·연락처·정산 계좌, 알림 4종(예약·문의·자동확정·소식), 전체 노출 토글, 탈퇴 | 완료 |

## 4. 고객 → 호스트 예약 흐름

```
고객 상세 페이지 ─ [예약 요청하기] ─▶ 모달(날짜·시작·시간·인원·목적·이름·연락처·요청사항·동의)
        │
        ├─ 인증 공간(A/B): POST /api/booking/request → 요청번호 BK-xxxx → "호스트에게 전달됨"
        │                   → 호스트 센터 예약 관리에 '프빗 요청'으로 표시 → 확정/거절
        │
        └─ 미인증 공간(D): 요청서 생성 → 내용 복사 버튼 + 네이버지도/전화/예약 링크로 직접 문의 안내
                            (호스트 입점 시 자동 전달)
```

- 결제: 현재는 호스트의 기존 방식(계좌·현장·네이버예약)으로 안내. 모달과 호스트 센터에 명시.
- 자체 결제 오픈 시 흐름: 요청 → 확정 시 카드 결제(PG) → 이용 완료 자동 처리 → 주 단위 정산 → 세금계산서 자동 발행. 취소·환불은 호스트가 고른 정책 템플릿으로 자동 계산.

## 5. 데이터 구조

### 입점 신청 (`/api/host/apply` payload)
```json
{
  "ref": "PV-20261107-A3K9",
  "checks": { "independent": true, "exclusive": true, "reservation": true, "nooutsider": true, "toilet": false },
  "basic": { "name": "", "owner": "", "phone": "", "email": "", "bizNo": "", "addr": "", "addrDetail": "", "claimId": "" },
  "space": { "c1": "", "c3": "", "minPeople": 2, "maxPeople": 8, "area": "", "open": "10:00", "close": "24:00", "days": [], "amenities": {}, "facilities": "", "intro": "", "privacyDesc": "" },
  "price": { "model": "hour", "base": "", "weekend": "", "minHours": 2, "extraPerson": "", "night": "", "deposit": "", "cancel": "std", "cancelCustom": "", "channels": ["pvit"] },
  "links": { "naver": "", "reserve": "", "home": "", "insta": "", "kakao": "", "photos": ["파일명"] },
  "photoCount": 0
}
```

### 예약 요청 (`/api/booking/request` payload)
```json
{ "ref": "BK-20261107-X9K2", "spaceId": "PVIT-11801", "spaceName": "", "region": "서울 용산구",
  "date": "2026-11-10", "start": "19:00", "hours": 3, "people": 4, "purpose": "생일",
  "name": "", "phone": "", "memo": "", "verified": false }
```

### 저장 위치
- 서버: Cloudflare KV `PVIT_KV` — 키 `apply:<ref>`, `booking:<ref>`, `contact:<id>`, 인덱스 `<prefix>:_index`
- 알림: `NOTIFY_WEBHOOK` 환경변수(Slack/Discord/Make 웹훅)에 접수 즉시 전송
- 브라우저: `localStorage` `pvit:*` — 임시저장·찜·데모 상태. 서버 저장 실패 시에도 사용자 흐름은 끊기지 않음

## 6. 관리자 관점 (다음 단계)

현재는 KV 에 쌓인 신청을 Cloudflare 대시보드 또는 웹훅으로 확인합니다. 다음 단계:
1. `/admin` 페이지(Access 로 보호) — 신청 목록, 승인/보완 버튼, 승인 시 `spaces.json` 항목 자동 생성
2. 승인 → 호스트에게 이메일(Resend 등) → 호스트 센터 상태 `live` 전환
3. 호스트 계정(이메일 매직링크) → 호스트 센터 게이트 교체
4. 자체 예약·결제(토스페이먼츠) → 정산 탭 실데이터
