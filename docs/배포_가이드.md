# 배포 가이드 — GitHub ↔ Cloudflare Pages

한 번 연결해 두면, 이후에는 GitHub 에 올릴 때마다 사이트가 자동으로 새로 만들어집니다. zip 을 다시 올릴 필요가 없습니다.

> **현재 운영 상태 (2026-11-16)** — Cloudflare Pages 프로젝트 `pvit-web` 이 GitHub `naadaa87/pvit` 의 `main` 브랜치와 연결되어 있고, `pvit.kr`·`www.pvit.kr` 이 이 프로젝트에 붙어 있습니다. push 하면 자동 배포됩니다.
> 예전 zip 업로드 프로젝트 `pvit` 는 도메인을 뺀 상태로 남아 있습니다 (삭제해도 무방).

## 1. 처음 연결하기 (10분)

1. **dash.cloudflare.com** 로그인 → 왼쪽 **Workers 및 Pages** → **생성** → **Pages** 탭 → **Git에 연결**
2. GitHub 계정 연결 → 저장소 **naadaa87/pvit** 선택 → **설정 시작**
3. 빌드 설정:
   - 프레임워크 사전 설정: **None** (또는 Vite)
   - 빌드 명령: `npm run build`
   - 빌드 출력 디렉터리: `dist`
   - 루트 디렉터리: 비워둠
   - 환경 변수 (선택): `NODE_VERSION` = `20`
4. **저장 및 배포** → 2~3분 뒤 `https://<프로젝트명>.pages.dev` 생성 → 이후 사용자 지정 도메인 `pvit.kr` 연결 (5번)

이미 직접 업로드로 만든 `pvit` 프로젝트가 있다면 이름이 겹치므로, 새 프로젝트 이름을 `pvit-web` 처럼 다르게 하거나 기존 프로젝트를 삭제한 뒤 진행하세요.

## 2. 이후 수정 → 반영

GitHub 저장소에 push 하면 끝입니다. Cloudflare 가 자동으로 빌드·배포합니다. (GitHub 웹에서 파일을 직접 고쳐 Commit 해도 됩니다.)

## 3. 호스트 신청·예약 요청을 서버에 저장하기 (KV)

사이트는 KV 없이도 동작하지만(이 경우 신청 내용은 신청자 브라우저에만 저장), 실제로 접수하려면 KV 를 붙입니다.

1. Cloudflare 대시보드 → **Workers 및 Pages** → **KV** → **네임스페이스 생성** → 이름 `PVIT_DB`
2. Pages 프로젝트 → **설정** → **바인딩** (또는 Functions) → **KV 네임스페이스 바인딩 추가**
   - 변수 이름: `PVIT_KV`
   - KV 네임스페이스: `PVIT_DB`
3. 재배포 → 이후 `/api/host/apply`, `/api/booking/request`, `/api/contact` 로 들어온 내용이 KV 에 저장됩니다.
4. 확인: `https://도메인/api/health` → `{"ok":true,"kv":true}`

KV 내용 보기: 대시보드 → KV → PVIT_DB → 키 목록 (`apply:PV-...`, `booking:BK-...`, `contact:...`). `apply:_index` 에 최신순 목록이 있습니다.

## 4. 접수 즉시 알림 받기 (웹훅)

Slack·Discord·카카오워크·Make 등 웹훅 URL 하나면 됩니다.

1. Pages 프로젝트 → **설정** → **환경 변수** → 추가
   - 이름: `NOTIFY_WEBHOOK`
   - 값: 웹훅 URL
2. 재배포 → 신청·예약 요청·문의가 들어오면 바로 메시지가 옵니다.

## 5. 내 도메인 연결 (예: pvit.kr)

1. 도메인 구매(가비아·후이즈 등)
2. Pages 프로젝트 → **사용자 지정 도메인** → **도메인 설정** → 안내대로 네임서버 또는 CNAME 설정
3. `src/lib/seo.jsx` 의 `SITE.url` 을 `https://pvit.kr` 로 수정 → push
4. Pages 환경 변수 `SITE_URL` = `https://pvit.kr` 추가 (사이트맵·robots 반영)
5. 서치어드바이저·서치콘솔에 새 도메인 등록 (docs/SEO_전략.md 참고)

## 6. 주의할 점

- **`_redirects` 파일을 만들지 마세요.** Cloudflare Pages 는 리다이렉트 규칙을 정적 파일보다 먼저 적용해서, `/* /index.html 200` 같은 규칙이 있으면 사전 렌더링된 페이지(SEO 용)가 모두 가려집니다. 404.html 도 두지 않습니다(그래야 SPA 폴백이 유지됩니다).
- 빌드에 Playwright 가 필요 없습니다. `npm run og`(OG 이미지 재생성)만 로컬에서 실행하세요.
- Netlify 에 올리는 경우에만 `public/_redirects` 에 `/* /index.html 200` 을 넣으면 됩니다(Netlify 는 정적 파일이 우선).

## 7. 로컬에서 Functions 까지 테스트하려면 (선택)

```bash
npm install -g wrangler
npm run build
wrangler pages dev dist --kv PVIT_KV
```
`http://localhost:8788` 에서 API 포함 전체 동작을 확인할 수 있습니다.
